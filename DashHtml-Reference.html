PowerShell Module Reference

DashHtml

Generate interactive, self-contained HTML dashboards from PowerShell — sortable tables, KPI tiles (with sparklines, deltas, big-number and gauge styles), line / area / pie / bullet / stacked-bar charts, RAG status matrix, event feeds, alert banners, filter cards, collapsible sections, drill-down linking, and client-side CSV / XLSX / PDF export. Six theme families (including the v1.4 Rag family with the Office/Excel palette), embedded light/dark variants, no external dependencies at viewing time.

INIT
New-DhDashboard
Create a new DashHtml dashboard definition object.
INIT

Returns an ordered dictionary that acts as the root object for all subsequent Add-DhTable, Set-DhTableLink and Export-DhDashboard calls.

Both the light and dark variants of the chosen theme are always embedded directly in the HTML output — no external CSS file is ever written. A toggle button in the nav bar lets viewers switch between light and dark at runtime without any server round-trip.

Syntax
New-DhDashboard -Title <String> [-Subtitle <String>] [-LogoPath <String>] [-Theme <String>] [-NavTitle <Object>] [-InfoFields <Object[]>] [-GeneratedBy <String>] [-AutoRefresh <String>]
Parameters
ParameterTypeRequiredDescription
-Title <String> required

Main heading shown in the sticky report header.
-Subtitle <String> optional

Optional sub-heading / description line beneath the title.

default: ''
-LogoPath <String> optional

Path to an image file. The image is Base64-encoded and embedded directly in the HTML so the report is portable with no external image references. Accepted formats: .jpg .jpeg .png .gif .webp

default: ''
-Theme <String> optional

Theme family for the dashboard. The light variant is shown on load; the dark variant is the runtime-toggle alternate. Both are always embedded. Valid values (default: Default): Default - System UI fonts. Light: light grey + blue. Dark: near-black + cyan. Azure - Segoe UI (system). Light: warm grey + Azure blue. Dark: Office dark + Azure. VMware - Inter (Google). Light: white/navy + VMware green. Dark: navy + VMware green. Grey - System UI fonts. Light: warm grey + steel. Dark: dark neutral + muted grey. Company - Montserrat (Google). Light: white + Crimson. Dark: near-black + Crimson. Use Get-DhTheme to list families and inspect their CSS.

default: 'Default'
-NavTitle <Object> optional

Text shown in the sticky nav bar alongside the navigation links. Defaults to the dashboard Title. Set to an empty string to suppress the label entirely (logo + links only). -NavTitle '' # hide entirely -NavTitle 'My Dashboard' # short form
-InfoFields <Object[]> optional

Optional array of @{ Label='X'; Value='Y' } hashtables rendered as a key-value grid in the report header alongside the title and logo. Example: -InfoFields @(@{Label='Environment';Value='Production'},@{Label='Region';Value='West'})
-GeneratedBy <String> optional

Optional script/tool name shown in the report footer.

default: ''
-AutoRefresh <String> optional

v1.4.2+ — auto-refresh interval. Accepts seconds as an int or a duration string like '30s', '5m', '1h'. When set, the exported HTML carries a <meta http-equiv="refresh"> tag so wall-display dashboards re-fetch the file automatically. Omit / pass '' / pass 0 to disable.

default: ''
Examples

EXAMPLE 2 Example 2

OUT
Export-DhDashboard
Write the self-contained HTML dashboard to disk.
OUT

Generates a single self-contained HTML file. Both the light and dark CSS themes are embedded directly inside the HTML — no external CSS file is ever written. A toggle button in the nav bar lets viewers switch themes at runtime.

The HTML also embeds: - All table data as JSON (no server round-trips) - The full JavaScript table engine (sort / filter / page / link / export) - The logo as a Base64 data URI (if supplied to New-DhDashboard)

External JS libraries referenced from cdnjs (internet required for export): - SheetJS xlsx v0.18.5 - XLSX export - jsPDF v2.5.1 - PDF export - jsPDF-AutoTable v3.8.2 - PDF table formatting

If the machine opening the report has no internet access, CSV export (pure JS, no CDN dependency) continues to work; XLSX and PDF buttons will show an alert.

KPI

Renders a horizontal strip of summary cards. Each tile shows an optional icon, a formatted value, a label, and an optional sub-label. Tiles can be coloured with the same threshold classes used on table cells.

Add-DhAlertBanner
Add a top-of-page alert banner to the dashboard.
ALERT

Renders a strip *above* the KPI summary tiles. Useful for surfacing current operational conditions — open incidents, recent failures, compliance breaches — so they are visible the moment the report opens.

Multiple banners can be added; they stack vertically in the order they were declared. Each banner carries a severity (info / ok / warning / critical) which drives the colour via the existing RAG palette.

Optionally: -Dismissible — adds a close button; the dismissal is remembered in the URL hash so it survives a page reload. -Action — adds a button that either navigates to a registered table (with an optional pre-filter) or opens an external URL.

Distinct from Add-DhEventFeed (v1.4+): a banner surfaces a single current condition; an event feed lists a chronological audit trail.

Add-DhPieChart
Add a standalone pie or donut chart block to the dashboard.
CHART

Renders a pie / donut chart as a top-level block in the dashboard flow. Two data modes:

Mode A — derive from a registered table: -TableId / -Field [ -TopN ] [ -ClickFilters ] Counts distinct values of the field across the table's rows. With -ClickFilters, clicking a slice applies the slice label as a text filter on the source table.

Mode B — explicit slices: -Slices @( @{ Label='...'; Value=...; Color='...' } ... ) Values are taken as-is. Use this for non-tabular data such as cost breakdowns or weighted distributions.

The 'donut' style (default) leaves a hole in the centre and prints the total value there. 'pie' renders a solid disc.

Per the IT-infrastructure KPI dashboard specification: "Avoid Pie Charts for more than 5 segments — use a horizontal bar chart instead." Use -TopN to cap segments or switch to Add-DhBarChart.

Add-DhLineChart
Add a line or area chart with axes, multi-series support, and an optional target / threshold annotation.
CHART

Renders a time-series style chart as a top-level block. Pure SVG, no external library. Single or multiple series share a common X-axis of category labels (timestamps, day names, etc.). Optional `-Filled` switches each series from a polyline to a filled area.

DashHtml

A PowerShell 7 module for generating interactive, self-contained HTML dashboards from any structured data — sortable/filterable tables, KPI tiles, bar charts, collapsible sections, and clickable filter cards. The output is a single HTML file with all data and styles embedded — no external dependencies at viewing time.

Features

  • Self-contained output — one HTML file, no companion CSS or JS files
  • Sortable, filterable, pageable tables — multi-column sort (Shift+Click), text filter, configurable page size
  • KPI summary tiles — icons, formatted values, threshold colouring
  • Bar charts — horizontal proportional bars, click-to-filter support
  • Clickable filter cards — single or multi-select, instant table filtering
  • Collapsible sections — key-value card grids or free-form HTML
  • Master-detail table linking — clicking a row filters a child table
  • Two-tier navigation — flat nav or grouped primary-tabs + subnav strip
  • Client-side export — CSV (no CDN), XLSX and PDF (cdnjs, requires internet)
  • Light/dark theme toggle — both variants embedded, switchable at runtime
  • Six theme families — Default, Azure, VMware, Grey, Company, Rag (the v1.4 family using the Office/Excel-compatible RAG palette)
  • Column features — progress bars, badges, threshold colouring, row highlighting, pinned first column, footer aggregates, number/currency/bytes/percent/datetime/duration formatting

Requirements

  • PowerShell 7.0 or later

Declaration order (important)

Always declare a table before any object that references it. This is the single most common source of "filter does nothing" / "chart is empty" / "link broken" issues.

The cmdlets below depend on a previously declared table identified by its -TableId / -TargetTableId / -MasterTableId / -DetailTableId. If the referenced table has not been added yet when the dependent cmdlet runs, the binding silently fails (the referenced data simply isn't available to bind against):

Dependent cmdlet Depends on
Add-DhFilterCard -TargetTableId must already exist
Add-DhBarChart -TableId must already exist
Set-DhTableLink both -MasterTableId and -DetailTableId must already exist

Correct order

PowerShell
# 1. Tables first Add-DhTable -Report $report -TableId 'items' -Title 'Items' -Data $items Add-DhTable -Report $report -TableId 'groups' -Title 'Groups' -Data $groups # 2. Then anything that references them Add-DhFilterCard -Report $report -Id 'region-fc' -TargetTableId 'items' -FilterField 'Region' -Cards $cards Add-DhBarChart -Report $report -Id 'status-bc' -TableId 'items' -Field 'Status' Set-DhTableLink -Report $report -MasterTableId 'groups' -DetailTableId 'items' -MasterField 'GroupId' -DetailField 'GroupId'

Wrong order (filter / chart / link will not work)

PowerShell
# ❌ FilterCard declared before its target table Add-DhFilterCard -Report $report -Id 'region-fc' -TargetTableId 'items' -FilterField 'Region' -Cards $cards Add-DhTable -Report $report -TableId 'items' -Title 'Items' -Data $items

Tip: visual position vs. declaration order

When using -NavGroup, a filter card or bar chart will still render above its table in the UI even if the table was declared first — the layout engine groups related blocks visually. So you can keep the safe declaration order (tables first) without sacrificing the desired on-screen layout.

Unified -Rag parameter (v1.4+)

Threshold rules were historically spelled out as an array of Min/Max/Class hashtables (per column on Add-DhTable, per item on Add-DhSummary). v1.4 adds a more readable Rag alternative that maps directly to the spec's GREEN / AMBER / RED / GREY bands. Both shapes are accepted; when both are supplied on the same item or column, Rag wins.

PowerShell
# Defined once, reused on a gauge and on two table columns $cpuRag = @{ Green = @{ Max = 70 } Amber = @{ Min = 70; Max = 90 } Red = @{ Min = 90 } NoData = $true # ← paint null / missing cells with cell-nodata } Add-DhSummary -Report $report -Items @( @{ Style='gauge'; Label='CPU'; Value=42; Max=100; Unit='%'; Rag=$cpuRag } @{ Style='gauge'; Label='Disk'; Value=95; Max=100; Unit='%'; Rag=$cpuRag } @{ Style='gauge'; Label='Net'; Value=$null; Max=100; Unit='%'; Rag=$cpuRag } # → cell-nodata ) Add-DhTable -Report $report -TableId 'srv' -Title 'Servers' -Data $rows -Columns @( @{ Field='Host'; Label='Host' } @{ Field='Cpu'; Label='CPU %'; Align='right'; Rag=$cpuRag } @{ Field='Mem'; Label='Mem %'; Align='right' Rag=@{ Green=@{Max=80}; Amber=@{Min=80;Max=95}; Red=@{Min=95}; NoData=$true } } )

Allowed keys on the Rag hashtable:

  • Green — maps to cell-ok. Hashtable with optional Min and/or Max.
  • Amber — maps to cell-warn. Same shape.
  • Red — maps to cell-danger. Same shape.
  • NoData — boolean. When $true, null / empty / non-numeric cell values render with cell-nodata instead of being left blank. Also lets a gauge accept Value=$null and paint itself grey.

Bounds are interpreted as Min ≤ value < Max (either bound may be omitted). Unknown keys throw — typos surface as errors instead of silently doing nothing. The legacy Thresholds=@(@{Min=...;Max=...;Class='cell-...'}) shape on columns and Thresholds= on tile items keeps working unchanged for backward compatibility.

cell-nodata — fourth RAG state across all themes (v1.4+)

Every theme now defines --cell-nodata-fg / --cell-nodata-bg so missing / unmeasured / collection-failed values can be marked visually distinct from 0 or OK. Available as cell-nodata everywhere cell-ok / cell-warn / cell-danger worked previously: table cell thresholds, summary tile Class, html-block -Style 'nodata', collapsible card BadgeClass, and the badge-nodata / fill-nodata / row-hl-nodata modifiers. Non-Rag themes pick a brand-appropriate neutral grey for the foreground.

PowerShell

Trend and delta indicators on tiles (v1.4+)

Each tile can show how its current Value compares to a previous baseline. Supply Previous, and an arrow + delta line appears between the value and the label:

  • ▲ +12 (+5.5%) (green) — Active users 231 vs previous 219
  • ▼ -8 (-3.2%) (red) — regression
  • ▶ ±0 (grey) — no change
PowerShell
Add-DhSummary -Report $report -Items @( # Auto-derived delta: up = good by default @{ Label='Active users'; Value=231; Previous=219 } @{ Label='Revenue'; Value=99450.75; Previous=92330.25; Format='currency'; Locale='en-US'; Currency='USD'; Decimals=2 } # Inverted semantics — fewer errors is GOOD news, paint green when down @{ Label='Errors (24h)'; Value=4; Previous=12; TrendIsGood=$true; Class='cell-warn' } @{ Label='Latency p95'; Value=82; Previous=88; TrendIsGood=$true; DeltaFormat='absolute' } # Explicit trend with no baseline number @{ Label='Pipeline'; Value=12; Trend='up' } )

Per-item keys (all optional):

  • Previous — baseline value. When supplied, the arrow direction and delta numbers are computed automatically.
  • Trend — 'auto' (default — derived from Previous), 'up', 'down', or 'flat'. Pass an explicit value to override the auto direction, or to show a direction without a numeric baseline.
  • TrendIsGood — flip the colour semantics for "lower is better" metrics. By default up is green (good) and down is red (bad). Pass $true to paint this direction as good regardless (e.g. errors trending down), or $false to mark it as bad.
  • DeltaFormat — 'both' (default, +12 (+5.5%)), 'percent' (just +5.5%), or 'absolute' (just +12).

When Previous is 0 only the absolute delta is shown (percent is undefined). The arrow alone is rendered when only Trend is supplied without Previous.

Stacked mode (v1.4+): pass -SeriesField to break each primary bar into colour-coded segments. The legend below the chart maps each series value to its colour. The -Stacked switch is optional — supplying -SeriesField alone implies it. Click-to-filter (-ClickFilters) is single-series only; stacked bars have no single value to filter by. Series colours are pulled from the active theme's chart palette and assigned in alphabetical order, so the legend stays stable across renders.

Pie / Donut charts

Standalone pie or donut chart as a top-level block. Supports two data modes:

  • Mode A — derive from a registered table. Counts distinct values of a field across all rows; sorts highest-to-lowest; caps at TopN segments.
  • Mode B — explicit slices. Provide Label/Value (and optional Color) hashtables directly. Use this for non-tabular data (cost breakdowns, weighted distributions).

The donut style (default) leaves a hole in the centre with the total; pie renders a solid disc.

Spec guidance: the IT-infrastructure KPI dashboard spec recommends avoiding pies with more than 5 segments — switch to Add-DhBarChart for higher cardinality.

PowerShell
# Mode A — derive from a table column Add-DhPieChart -Report $report -Id 'status-pie' ` -Title 'Items by status' ` -TableId 'items' -Field 'Status' -ClickFilters # Mode B — explicit slices, donut style Add-DhPieChart -Report $report -Id 'cost-pie' ` -Title 'Monthly cost by region' -Style 'donut' ` -Slices @( @{ Label='us-east'; Value=12500 } @{ Label='eu-west'; Value=8200 } @{ Label='ap-south'; Value=3400 } ) # Pie style, custom colours, no legend Add-DhPieChart -Report $report -Id 'license-pie' ` -Title 'License usage' -Style 'pie' -ShowLegend $false ` -Slices @( @{ Label='Used'; Value=820; Color='#1B6B35' } @{ Label='Available'; Value=180; Color='#8B5200' } )

Key parameters:

  • -Style — 'donut' (default) or 'pie'
  • -TableId / -Field — Mode A only; the source table must already be added
  • -TopN — Mode A only; cap at N segments (default 10)
  • -ClickFilters — Mode A only; clicking a slice applies the slice label as a text filter on the source table
  • -Slices — Mode B only; mutually exclusive with -TableId
  • -ShowTotal — show the total in the donut hole (default $true; ignored for pie style)
  • -ShowLegend — show the label / count / percentage rows (default $true)

Line / Area charts (v1.4+)

Time-series-style chart as a top-level block. Multiple series share one X-axis of category labels (typically timestamps). Optional -Filled switches the lines into filled areas. Optional -TargetLine draws a dashed horizontal annotation at a Y value, which the spec (§7.4) calls out as the canonical pairing for any time-series visualisation: "Always pair a time-series chart with a threshold annotation line."

PowerShell
$hours = @('00:00','04:00','08:00','12:00','16:00','20:00','24:00') # Single series with a warning-threshold annotation Add-DhLineChart -Report $report -Id 'cpu-trend' -Title 'Cluster CPU (24h)' ` -XAxis $hours ` -Series @( @{ Label='Avg'; Values=@(42,38,55,67,71,68,52); Class='cell-ok' } ) ` -TargetLine 70 -TargetLabel 'Warning threshold' ` -YAxisMin 0 -YAxisMax 100 -YAxisUnit '%' # Multi-series filled area chart Add-DhLineChart -Report $report -Id 'net-bw' -Title 'Network throughput (Mbps)' ` -Filled ` -XAxis $hours ` -Series @( @{ Label='Ingress'; Values=@(800,950,1100,1240,1200,1180,900); Class='cell-ok' } @{ Label='Egress'; Values=@(600,700,820,910,880,850,720); Class='cell-warn' } ) # Gap handling — $null entries break the line at that index Add-DhLineChart -Report $report -Id 'replication-lag' -Title 'Replication Lag' ` -XAxis $hours ` -Series @( @{ Label='DC01→DC02'; Values=@(2,3,$null,$null,5,4,3); Color='#0088BB' } @{ Label='DC01→DC03'; Values=@(1,2,2,3,2,2,1); Color='#E08800' } ) ` -TargetLine 60 -TargetLabel 'SLA 60s' -YAxisUnit 's'

Parameters:

  • -XAxis — array of category labels (typically timestamps). Must have ≥ 2 entries.
  • -Series — array of @{Label;Values[];Class;Color}. Each series's Values length must match XAxis. Class maps to the RAG palette (cell-ok / cell-warn / …); Color is an explicit override. $null entries in Values are allowed and rendered as line breaks.
  • -Filled — switch; renders each series as a filled area instead of a polyline.
  • -TargetLine / -TargetLabel — optional numeric reference Y and its label. Dashed line drawn in the warning colour.
  • -YAxisMin / -YAxisMax / -YAxisUnit — explicit Y-axis bounds (auto-fitted with 5% padding when omitted) and an optional unit suffix on tick labels ('%', 'ms', 'GB' etc.).
  • -ShowLegend / -ShowGrid — defaults $true. Disable for compact embeds.
  • -Height — SVG height in px (80–1000, default 240).

The plot stretches to fit its container horizontally; height is fixed by -Height.

Status Grid (v1.4+)

Rows × columns RAG matrix — the IT-infrastructure KPI dashboard specification's "Status Matrix / Health Grid" (§2). Use it for at-a-glance health overviews where many entities share a small set of states: services × regions, DCs × replication links, hosts × probes. A status grid is a colour-first matrix; if your data needs sortable columns or rich cell content, use Add-DhTable instead.

PowerShell
Add-DhStatusGrid -Report $report -Id 'service-health' -Title 'Service Health' ` -RowLabel 'Service' -ColumnLabel 'Region' ` -Rows @('Auth','Billing','Search','Mail','Payments') ` -Columns @('us-east','us-west','eu-west','eu-central','ap-south') ` -CellSize 'normal' ` -Cells @( @{ Row='Auth'; Column='us-east'; Status='ok'; Tooltip='99.98% / 24h' } @{ Row='Auth'; Column='eu-west'; Status='warn'; Tooltip='latency spike' LinkTableId='incidents'; LinkFilter='auth-eu' } @{ Row='Billing'; Column='us-east'; Status='danger'; Tooltip='down 12m' } @{ Row='Billing'; Column='ap-south'; Status='nodata' } # ... declare only the (Row, Column) pairs that exist )

Per-cell keys:

  • Row — required string, must appear in -Rows. Typo throws (no silent miss).
  • Column — required string, must appear in -Columns.
  • Status — required. One of 'ok' / 'warn' / 'danger' / 'nodata' / 'info'. Drives the cell colour via the existing RAG palette.
  • Tooltip — optional string. Renders as the native title="" hover tooltip; no popover library.
  • LinkTableId — optional. Clicking the cell jumps to this registered table (reuses the same panel-navigation hook as Add-DhAlertBanner -Action).
  • LinkFilter — optional. When LinkTableId is set, the table receives this text filter on jump. Filter without LinkTableId throws.

Cmdlet parameters:

  • -Rows / -Columns — required string arrays defining the axes.
  • -RowLabel / -ColumnLabel — optional axis captions shown in the top-left corner of the grid.
  • -CellSize — 'small' (32 px) / 'normal' (48 px, default) / 'large' (64 px). Below a 600 px viewport, the grid collapses to a stacked list regardless of this setting.
  • -MaxCells — hard ceiling on Rows × Columns (default 2000). A soft warning fires above 200 cells.

Cells you don't declare render as a faint dashed neutral state. A legend strip below the grid auto-generates from the statuses actually present.

Event feed (v1.4+)

Chronological severity-tagged audit trail. Per the IT-infrastructure KPI dashboard specification (§4.1 and §4.2), this is the canonical Row 5 of an ops dashboard — the evidence trail that pairs with the at-a-glance KPI tiles above. Distinct from Add-DhAlertBanner (which surfaces a single current condition at the top of the page).

PowerShell
Add-DhEventFeed -Report $report -Id 'recent-events' ` -Title 'Recent events (24h)' -MaxItems 50 ` -Events @( @{ Timestamp='2026-05-22 14:32'; Severity='critical'; Source='DC01' Message='Replication failure to DC03' } @{ Timestamp='2026-05-22 14:18'; Severity='warning'; Source='DC02' Message='LDAP bind time > 80 ms (avg)' } @{ Timestamp='2026-05-22 13:55'; Severity='info'; Source='vSphere' Message='vMotion: VM-027 → ESXi-04' } @{ Timestamp='2026-05-22 12:42'; Severity='ok'; Source='Backup' Message='Nightly backup completed in 42 minutes' } ) # Optional grouping — critical floats to the top Add-DhEventFeed -Report $report -Id 'incidents-by-sev' ` -Title 'Open incidents' -GroupBy 'Severity' -Events $incidents

Per-event keys:

  • Timestamp — required string. Free-form — sorted lexicographically. ISO-8601 timestamps sort correctly out of the box.
  • Severity — required. One of 'info' / 'ok' / 'warning' / 'critical'. Drives the row colour via the existing RAG palette.
  • Message — required string. Long messages wrap onto a second line.
  • Source — optional string. Rendered in [brackets] between the timestamp and the message.
  • Icon — optional emoji / glyph. Overrides the default severity icon (· / ✓ / ! / ✕).

Cmdlet parameters:

  • -MaxItems — cap on visible rows (default 50, range 1..1000). Older events are dropped after sort+slice.
  • -GroupBy — 'None' (default) / 'Severity' / 'Source'. With grouping, each group is preceded by a header showing the group key and entry count. 'Severity' groups appear in priority order (critical → warning → ok → info).
  • -SortDescending — newest-first by default ($true). Pass $false for chronological top-down reading.

Bullet charts (v1.4+)

The canonical "actual vs target with performance bands" visualisation, per the IT-infrastructure KPI dashboard specification (§2 Widget Types). Each row stacks vertically and shows: a full-width track, RAG-coloured performance bands, a solid value bar from Min to Value, and an optional vertical target marker on top.

PowerShell
# Share one RAG definition across multiple rows $latencyRag = @{ Green = @{ Max = 50 } Amber = @{ Min = 50; Max = 80 } Red = @{ Min = 80 } } Add-DhBullet -Report $report -Id 'auth-latency' -Title 'LDAP Bind Time' -Items @( @{ Label='DC01'; Value=42; Target=50; Max=120; Unit='ms'; Rag=$latencyRag } @{ Label='DC02'; Value=68; Target=50; Max=120; Unit='ms'; Rag=$latencyRag } @{ Label='DC03'; Value=92; Target=50; Max=120; Unit='ms'; Rag=$latencyRag } )

For "bigger is better" metrics (headroom, uptime SLA), flip the RAG semantics:

PowerShell
Add-DhBullet -Report $report -Id 'cpu-headroom' -Title 'CPU Headroom per Host' -Items @( @{ Label='esxi-01'; Value=42; Target=30; Min=0; Max=100; Unit='%' Rag=@{ Green=@{Min=30}; Amber=@{Min=15;Max=30}; Red=@{Max=15} } } @{ Label='esxi-02'; Value=12; Target=30; Min=0; Max=100; Unit='%' Rag=@{ Green=@{Min=30}; Amber=@{Min=15;Max=30}; Red=@{Max=15} } } )

Per-item keys:

  • Label — left-side row label (required)
  • Value — actual numeric value (required)
  • Target — optional numeric. When set, a vertical tick mark appears on the track.
  • Min / Max — track range. Defaults 0..100; Max must be > Min.
  • Unit — optional suffix in the readout ('ms', '%', …)
  • Class — optional value-bar colour override ('cell-ok' / 'cell-warn' / 'cell-danger' / 'cell-nodata'). Wins over the auto threshold match.
  • Rag — preferred way to declare the bands (see Unified -Rag parameter).
  • Bands / Thresholds — legacy array shape @(@{Min;Max;Class}); Bands is an alias for Thresholds. Rag wins when both are supplied.

Two-tier navigation

Use -NavGroup on any cmdlet (Add-DhTable, Add-DhFilterCard, Add-DhBarChart, Add-DhHtmlBlock, Add-DhCollapsible) to create a grouped navigation with a primary tab bar and a sub-nav strip:

PowerShell
$report = New-DhDashboard -Title 'Operations Dashboard' # Filter card and bar chart placed at the top of the Identity group Add-DhFilterCard -Report $report -Id 'status-fc' -NavGroup 'Identity' ` -Title 'Filter by Status' -TargetTableId 'users' -FilterField 'Status' ` -Cards @( @{Label='Active'; Value='Active'}, @{Label='Disabled'; Value='Disabled'} ) Add-DhTable -Report $report -TableId 'users' -Title 'Users' -Data $users -NavGroup 'Identity' Add-DhTable -Report $report -TableId 'groups' -Title 'Groups' -Data $groups -NavGroup 'Identity' Add-DhTable -Report $report -TableId 'servers' -Title 'Servers' -Data $servers -NavGroup 'Infrastructure' Add-DhTable -Report $report -TableId 'disks' -Title 'Disks' -Data $disks -NavGroup 'Infrastructure' Export-DhDashboard -Report $report -OutputPath '.\ops.html' -Force

Result: primary nav shows Identity and Infrastructure group tabs. Clicking a group tab shows the subnav for that group. Blocks with a matching -NavGroup appear as persistent content above the sub-nav panel (e.g. filter cards remain visible while switching between tables in the same group). Groups composed entirely of blocks (no tables) are supported — the subnav strip is hidden automatically for those groups.

Three-tier navigation (optional)

Add an optional -NavSubGroup on top of -NavGroup to get a third level: a pill strip appears below the sub-nav when the active group has any subgroups. When a group with subgroups is opened, the first pill is automatically active, so items tagged with -NavSubGroup behave as a true subgroup binding — visible only when their pill is the active one. Clicking another pill switches the subgroup; clicking the active pill clears the filter and shows all items in the group. Items in a group that have no -NavSubGroup remain visible regardless of pill state, acting as group-wide content.

PowerShell
Add-DhTable -Report $report -TableId 'users-prod' -Title 'Users (Prod)' -Data $prodUsers ` -NavGroup 'Identity' -NavSubGroup 'Production' Add-DhTable -Report $report -TableId 'users-dev' -Title 'Users (Dev)' -Data $devUsers ` -NavGroup 'Identity' -NavSubGroup 'Development' Add-DhTable -Report $report -TableId 'users-all' -Title 'All Users' -Data $allUsers ` -NavGroup 'Identity' # no NavSubGroup → always visible in Identity

The parameter is available on every block cmdlet (Add-DhTable, Add-DhHtmlBlock, Add-DhCollapsible, Add-DhFilterCard, Add-DhBarChart) and is fully backward compatible — existing scripts work unchanged.
